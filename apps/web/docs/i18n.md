# i18n workflow (SP-010)

UI languages: `en`, `de`, `ar` (RTL), `uk`, `tr`. Learning content stays German (`lang="de"`).

## Message files

- Source of truth: `apps/web/messages/en.json`
- Other locales must contain the **same keys** (CI fails otherwise)
- Namespaces: `Common`, `Nav`, `Footer`, `Marketing`, `Learning`, `Auth`, `App`, `NotFound`, `Error`, `Errors`

```bash
pnpm --filter @sprachpilot/web i18n:check
```

## Adding a string

1. Add the key to `en.json`
2. Translate into `de.json` (human)
3. Translate / machine-translate `ar.json`, `uk.json`, `tr.json` and mark for review in the PR
4. Run `i18n:check`
5. Use `useTranslations` / `getTranslations` — no hard-coded user-facing copy

## Routing

- Locale prefix is always present: `/en`, `/de`, `/ar`, …
- Middleware detects `Accept-Language` on first visit and redirects
- Language switcher keeps the current path (`FR-2`)

## RTL

- `ar` sets `dir="rtl"` on `<html>`
- Prefer Tailwind logical utilities (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`)

## API errors

Map Problem Details `type` URIs with `apiErrorTypeToMessageKey()` → `Errors.*` messages.

## Formatting

Default timezone: `Europe/Berlin` (configured in `i18n/request.ts`). Use `createAppFormatter(locale)` for dates/numbers.
